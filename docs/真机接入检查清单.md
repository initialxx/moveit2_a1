
## 3. 分步验证

**原则：每一步通过了再进下一步。不要跳步。**

### 步骤 1：只读状态，不发命令

先确认能读到关节角，且**数值与真机实际姿态吻合**。

```bash
source setup_env.sh

# 仅连接 + 读状态，不接收轨迹（用一个最小的只读脚本）
python3 - <<'PY'
import time
from onero_sdk.can_backend import CanBackend
from onero_sdk.model_registry import get_model
m = get_model("A1R")
be = CanBackend(channel="can0", joint_specs=m.joints, recv_timeout=0.003)
try:
    for _ in range(5):
        s = be.get_state()
        print("  " + "  ".join(f"{v:+.3f}" for v in s.joints))
        time.sleep(0.5)
finally:
    be.close(disable=False)
PY
```

**验收**：打印出的 7 个角度与目视姿态一致（注意关节方向约定）。

- [ ] 能连上 CAN
- [ ] 7 个关节都有合理读数（不是全 0、不是 NaN）
- [ ] 手动轻轻推动某一关节，对应读数有变化

> ⚠️ 这一步**不要** enable，避免机械臂突然上力。

### 步骤 2：使能 + 保持当前位置

```bash
ros2 run onero_a1_bringup topic_bridge --ros-args \
  -p simulate:=false -p can_channel:=can0 -p model:=A1R \
  -p kp:=20.0 -p kd:=1.0          # ← 先用较低的 kp
```

**验收**：
- [ ] 日志出现「已连接 CAN 'can0' | 模型 A1R | 电机已使能」
- [ ] 机械臂**保持当前姿态**，没有突然下沉或抖动
- [ ] `ros2 topic echo /robot_joint_states --once` 数值合理

> kp 从小往大调。太小会「软」，撑不住自重；太大会震荡。

### 步骤 3：单关节小幅度点动

用话题桥直接发一个小目标（**不经过 MoveIt**）：

```bash
ros2 topic pub --once /robot_joint_commands sensor_msgs/msg/JointState \
"{name: ['joint1-a1_r'], position: [0.05]}"
```

**验收**：
- [ ] 关节 1 缓慢移动约 0.05 rad（≈3°）
- [ ] 其他关节不动
- [ ] 无异常噪音、无过流报警

- [ ] 通过后，再逐个测试其余 6 个关节的**方向是否正确**
      （方向错了说明 URDF 关节轴向与实际不符，必须停下排查）

### 步骤 4：经 MoveIt 执行完整轨迹

```bash
# 终端 1：完整链路（含 RViz）
ros2 launch onero_a1_moveit_config moveit.launch.py \
  hardware_mode:=real can_channel:=can0

# 终端 2：验收
python3 tools/test_moveit_e2e.py joint1-a1_r 0.2
```

**验收**：
- [ ] RViz 中的模型与真机姿态**一致**
- [ ] 规划出轨迹后真机平滑跟随
- [ ] 到位误差 < 0.05 rad
- [ ] `error_code = 1`

**先从小幅度、慢速开始。** 确认无误后再逐步加大。

## 4. 安全注意

### 4.1 速度限制

`joint_limits.yaml` 目前设为硬件上限的约 2/3：

| 关节 | 硬件上限 | 规划限位 |
|---|---|---|
| J1–J4 | 3.0 rad/s | **2.0** |
| J5–J7 | 6.0 rad/s | **3.0** |

**首次上真机建议再砍一半**，改 `joint_limits.yaml` 后重新编译。

### 4.2 RViz 里的速度/加速度缩放

MotionPlanning 面板的 `Velocity Scaling` / `Accel. Scaling` 默认 0.10，
可以先保持这个值。

### 4.3 看门狗

已默认启用（`watchdog_timeout:=1.0`）。**桥接节点失联会自动停用控制器。**

不要用 `watchdog_auto_deactivate:=false` 上真机。

### 4.4 软件安全 ≠ 硬件安全

本方案的防护只能覆盖「通信中断」类故障。**完整安全链必须包含**：

- 驱动器过流 / 过温保护
- **物理急停按钮**
- 机械限位
- 安全-rated 的控制架构（如需要）

## 5. 已知问题与待办

### 5.1 ⚠️ URDF 根连杆带惯量（KDL 警告）

RViz / move_group 启动时会打印：

```
[WARN] kdl_parser: The root link base_link has an inertia specified in the URDF,
but KDL does not support a root link with an inertia.
As a workaround, you can add an extra dummy link to your URDF.
```

**影响**：KDL 会忽略根连杆惯量。对本项目（固定基座）**运动学无影响**，
因为基座不参与运动；但严格来说不符合 KDL 的假设。

**两种修法**（需决定后再改）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 去掉根连杆惯量** | 在 `sync_description_from_sdk.py` 里删掉 `base_link` 的 `<inertial>` | 偏离权威 URDF（但基座固定，惯量对动力学无意义） |
| **B. 加虚拟根连杆** | 新增无惯量的 dummy link 作为根，`base_link` 变子连杆 | 改动运动学结构，SRDF 的 virtual_joint 也要跟着改 |

**当前状态**：未修改。因为这会偏离 armsdk 的权威 URDF，需先确认。

### 5.2 话题桥插件的实时性

`joint_state_topic_hardware_interface` 的 `read()` 里会调用 `spin_some`，
且每周期有两次跨进程通信。`update_rate` 目前是 100Hz（`ros2_controllers.yaml`）。

**若真机上出现抖动或跟不上**，可先降到 50Hz 试试，并实测周期耗时分布。

### 5.3 状态看门狗之外

桥接节点自身崩溃由看门狗覆盖。但若 **CAN 链路**本身出问题（丢帧/故障），
依赖 `on_fault_action` 处置，默认是 `log`（只记录）。

真机建议改成 `hold`：
```bash
-p on_fault_action:=hold
```
